# E6.5 Universe Expansion and Controlled Backfill (T051)

Status: executed 2026-09-09. Implements the T050 decision
(`docs/e6.4-cost-projection.md`, **QUOTE_HISTORY_VALVE**): trades for the
200-symbol liquid universe, quotes restricted to the top-25 by liquidity at
a one-year window. The operator mandate to start T051 is the recorded
approval to execute the valve scope. This document is the rollout record:
universe derivation, valve mapping, the incremental launch log, and the
cost cross-check against the T050 projection ($7.69/month).

## 1. Universe Derivation

Universe file: `config/lake/universe-equities-200.yaml` (200 symbols,
rank = list position, most liquid first). Soak configs reference it; the
soak driver reads the symbol list from each soak config.

Derivation, with the assumption set explicit:

1. **Constituent grounding.** The 167 single-name symbols were validated on
   2026-09-09 against the S&P 500 constituents table snapshot retrieved
   from Wikipedia ("List of S&P 500 companies", 504 unique tickers, table
   `constituents`). Every single name in the universe is a current
   constituent; zero mismatches after one correction (below). The 33 ETFs
   are not index constituents and are validated by listing knowledge only.
2. **Liquidity ordering.** Operator-curated approximation of trailing
   median daily notional traded value as of 2026-09-09, grouped into nine
   explicit bands (>=5B, 2-5B, 1-2.5B, 0.8-1.5B, 0.5-0.9B, 0.4-0.6B,
   0.25-0.45B, 0.2-0.35B, 0.15-0.3B USD/day). Order inside a band is
   approximate and not asserted; the selection of the 200 names and of the
   top-25 head block is the operative decision.
3. **Head anchor.** The list is headed SPY, QQQ, AAPL per the T050 handoff
   ("SPY, QQQ, AAPL head the ranked list").
4. **One listing per issuer.** GOOGL kept / GOOG dropped, FOXA kept /
   FOX dropped, NWS/NWSA dropped, BRK.B for Berkshire.
5. **Delisting correction.** HES (Hess) was removed: it is not in the
   2026-09-09 constituent snapshot (delisted after the 2024 Chevron
   acquisition). Replaced by PLD (Prologis), present in the snapshot.
6. **ETF inclusion.** The 33 most-traded US-listed ETFs are included
   because the valve's most liquid names are ETFs (SPY, QQQ, IWM head the
   list) and the existing soak universe already includes SPY.
7. **Valve insensitivity.** Per-session quote cost is uniform across
   symbols, so the top-25 cost envelope holds for any 25-symbol head set of
   equivalent liquidity; intra-band ordering errors shift which names get
   quotes, not the cost.

Composition: 167 single names + 33 ETFs = 200. Ranks 1-25 (the quote arm):
SPY, QQQ, AAPL, TSLA, NVDA, AMD, AMZN, MSFT, META, GOOGL, PLTR, IWM, NFLX,
F, T, BAC, PFE, INTC, WFC, C, VZ, DIS, V, JPM, XOM.

## 6. Findings

- **F1 - Dual-type ensure side effect (valve leakage).** The deployed
  ensure path publishes BOTH data types for every ensured session:
  `EquityIngestTransaction.run` fetches trades and quotes together and
  commits both coverage rows and both objects
  (`src/lake/ingestion/equities/transaction.py:91-99`, staging at
  `:141-174`, dual coverage at `:176-203`); the hosted launcher never
  consults the requested `data_type` (`src/lake/hosted/runtime.py:200-253`).
  Consequence: the trades arm side-effect-published quote objects for all
  200 symbols (that is why 400 quote objects exist for two sessions). At
  the bounded ingest depth the leakage is ~11.7 KB per session-pair and
  immaterial (full-backfill projection +~6.3 GB, +~$0.06/month Cool). At
  future FULL depth it multiplies the quote corpus by 8x versus the
  top-25 valve (43 TB-class), so **before any unbounded ingest path
  exists, the transaction must honor the requested data type or the valve
  must be re-decided with the leakage accounted** (T050 handoff item 4
  applies). Until then the trades window bounds everything: keep it
  resumable and never widen the window without re-running the T050 model.
- **F2 - Container listing truncation.** `az storage blob list` page
  limit (5,000 entries) makes whole-container sums unreliable (HNS
  directory entries dominate the tail). Measure per-date prefixes.
- **F3 - Bounded ingest depth.** Every recorded session was capped at
  1,000 rows at capture time (that operator setting has since been removed;
  the lake now pages each fetch until the provider cursor is exhausted),
  ~10.8-19.6 KB per object. Recorded rows/bytes are lower bounds on SIP
  depth, as documented by the e6 runbook; the corpus therefore stays orders
  of magnitude below the full-depth planning numbers until the internal
  budget is raised.

## 7. Cost Cross-Check vs the T050 Projection ($7.69)

1. **Model reproduction.** `uv run --extra dev python
   scripts/cost/e6_4_projection.py --scenario valve --format table`
   reproduces the T050 row exactly: 751.037 cool GiB, 7.5104 storage +
   0.1130 compute = **7.6910 USD/month**, storage gate PASS (1 TiB), cost
   gate PASS (40 USD). Same constants, same decision.
2. **Envelope arithmetic.** The recorded $7.69 valve corpus is
   806.4 GB = 200 x 252 x 6.0 MB (one-year trades) + 25 x 252 x 80.0 MB
   (one-year quotes). Note the recorded valve priced the trades arm at
   one year; the committed trades config is full-history (2,686 sessions,
   3,223.2 GB at planning bytes) per the T051 spec, which exceeds the
   1 TiB planning ceiling **only under full-depth planning bytes**.
   Under the ingest bounded at 1,000 rows per session at capture time the
   projected real corpus for the
   full backfill is ~537,200 session-pairs x ~26.6 KB (measured trade
   14.8 KB + quote side effect 11.8 KB) ~= 14.3 GB ~= **$0.14/month**
   Cool (0.01 USD/GB-month), roughly 55x under the $7.69 envelope and
   75x under the 1 TiB ceiling. The T050 gate rule therefore holds for
   the executed rollout; re-run the model with `--decisions` before any
   widening (F1).
3. **Measured wave.** This session's 444 sessions cost **$0.0248
   incremental** (sum of the seven summary projections; Hot-prorated line
   items per the T049 cost model). One-time full-backfill compute at the
   measured ~4.6 s/request: ~2.47M s ~= $26 Container Apps compute spread
   over the backfill period, inside the deployed budget guards.
4. **Steady state monthly.** After the backfill, growth is 21
   sessions/symbol/month x 200 symbols x ~26.6 KB ~= 112 MB/month
   (+$0.001/month at Cool) - the recorded steady state remains dominated
   by the dev environment's fixed baseline (measured 3.94 USD/30d run
   rate, T050 baseline), not by the lake corpus.
5. **Guards.** Budgets `fca-ml-dev-budget-40usd` (40) and
   `fca-ml-dev-budget-70usd` (70) and the 1 TiB capacity pause
   (`pauseEnqueueAtCapacity`/`pauseIngestAtCapacity`) remain deployed and
   active throughout.

## 9. Resume Discipline

The rollout is resumable: re-running the same command skips every state
key already terminal and retries only failures. Next resume points:

```powershell
# Trades arm: full window, all 200 symbols (2,686 sessions/symbol;
# state file holds the 2 newest settled sessions for every symbol).
uv run --extra dev python scripts/soak/run_soak.py `
    --config config/lake/soak-valve-trades-200.yaml --base-url https://<api-fqdn>

# Quotes arm: one-year window, top-25 symbols (252 sessions/symbol).
uv run --extra dev python scripts/soak/run_soak.py `
    --config config/lake/soak-valve-quotes-top25.yaml --base-url https://<api-fqdn>
```

At the measured ~4.6 s/request the trades arm is ~28 days of one-replica
wall time across invocations; the quotes arm is ~7.5 hours. Apply the
runbook's temporary ingress posture for workstation invocations and
restore it after; check `az consumption budget list` during the campaign.
Post-F1, complete the quotes arm only after deciding whether the
dual-type side effect is accepted at full depth.
