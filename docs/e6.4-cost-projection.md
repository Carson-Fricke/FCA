# E6.4 Cost Projection and Equity Rollout Decision (T050)

Status: decision recorded, operator sign-off pending (block at the end of
this document). Model: `scripts/cost/e6_4_projection.py`. Baseline captured
2026-09-09 from the live dev environment (read-only Azure access only).

## Decision Rule (E6.4 AC1)

> A documented decision prevents broad backfill unless projected Cool
> storage and total monthly costs meet the plan gates.

The plan gates are the deployed budget composition in
`infra/modules/cost-controls.bicep` (composed in `infra/main.bicep` with
`budgetName = 'fca-ml-dev-budget'` and `logRetentionDays = 30`), confirmed
live on 2026-09-09 via `az consumption budget list -g fca-rg-westus2`:

| Gate | Deployed resource | Value |
| --- | --- | --- |
| First monthly budget alert (cost gate) | `fca-ml-dev-budget-40usd` | 40 USD/month, Actual >= 100% |
| Second monthly budget alert (hard ceiling) | `fca-ml-dev-budget-70usd` | 70 USD/month, Actual >= 100% |
| Storage capacity ceiling (storage gate) | runtime guardrail `storageCapacityBytes` | 1,099,511,627,776 bytes (1 TiB), enqueue/ingest pause |

Mechanical reading used by this decision: broad backfill is approved only
when the projected total monthly cost stays at or under the **first alert
(40 USD)** — so no budget alert ever fires — and the projected Cool-tier
corpus stays within the **1 TiB storage capacity ceiling**. Both conditions
must hold; the 70 USD budget is headroom, not a target.

## Decision

**QUOTE_HISTORY_VALVE** — the rule fired the valve branch. The broad
backfill scenario fails both gates (43.0 TiB Cool corpus; 430.26 USD/month
against the 40 USD gate). T051 (E6.5) proceeds under the ranked
quote-history valve, not with broad backfill.

Solved valve spec (largest fit under the 1 TiB ceiling at one-year
history, from `solve_valve_spec`):

- Trades: full 200-symbol universe, all available sessions per symbol.
- Quotes: **top-39 symbols only**, ranked by liquidity (most liquid
  first), one-year history.
- Recommended initial size for T051: **top-25 quotes** (the `valve`
  scenario below) rather than the solved maximum of 39, because the
  full-depth per-session bytes are order-of-magnitude planning numbers.
  The top-25 valve projects 751.0 GiB and 7.69 USD/month — both gates pass
  with margin. Runtime pause guardrails (`pauseEnqueueAtCapacity`,
  `pauseIngestAtCapacity`) remain the backstop as the corpus grows.

Consequences of the two branches, per the rule:

- **Approve branch** (not fired): E6.5/T051 would proceed with the
  full 200-plus symbol broad backfill at full SIP depth under the budget
  valve. Rejected: projected 430.26 USD/month exceeds the first budget
  alert by roughly 10.8x and the corpus exceeds the capacity ceiling by
  roughly 42x.
- **Valve branch (recorded)**: T051 executes the ranked quote-history
  valve — 200 symbols of trade history, quote history restricted to the
  top-N by liquidity (N=25 recommended, N=39 the computed maximum at
  one-year history) — and pauses at every configured budget guard.

### Azure permission and API limitations

1. **Cost Management query API throttled**: per-service GroupBy queries
   against the resource-group scope returned `429 Too Many Requests` on
   three attempts across roughly nine minutes of backoff (45 s, 90 s,
   300 s). No per-service actual-cost split could be captured.
2. **Legacy usageDetails stubs**: `az consumption usage list` returns
   deprecated placeholder rows (`pretaxCost: "None"`, null quantities), so
   it provides no per-meter cost either.
3. Fallback used (the one the task permits): the budget `currentSpend`
   anchor (a real Cost Management-derived number) plus documented
   list-price arithmetic over the measured storage bytes and soak
   volumes. Per-service attribution therefore comes from the model, not
   from billing rows; treat the baseline spend table as anchored by the
   1.1826 USD month-to-date figure.
4. All queries were read-only; nothing was created, modified, or deleted.

## Extrapolation Assumptions (explicit)

1. **Universe size**: T051 says "the approved 200-plus symbol universe"
   but no concrete symbol list is recorded yet. Assumption: exactly **200
   symbols**. The `scaled` scenario stress-tests 500 symbols. T056's
   options expansion (3 underlyings toward 10) is a separate epic and is
   not included in these numbers.
2. **History depth**: all-available history starts 2016-01-01, which the
   soak runbook plans at **2,684 closed sessions per symbol per data
   type** — 10.65 years at the model's 252 sessions/year. The valve and
   scaled scenarios use 1.0 and 3.0 years respectively.
3. **Full-depth bytes per session**: the deployed ingest is bounded at
   `LAKE_INGEST_MAX_RECORDS=1000` records per data type, so measured soak
   bytes (~10-13 KB/session) are lower bounds. Full-depth projections use
   the order-of-magnitude planning bytes from
   `config/lake/soak-aapl-spy.yaml`: trade 6.0 MB/session and quote
   80.0 MB/session (the SPY-side values — most watchlist names are less
   liquid than SPY, so this is a conservative upper proxy). The `scaled`
   scenario uses the AAPL/SPY midpoint (3.75 MB / 55 MB). These must be
   replaced by real full-depth measurements once an unbounded ingest path
   exists (runbook fidelity note).
4. **Cool tier prices** — source: Azure Retail Prices API
   (`prices.azure.com`, api-version `2023-01-01-preview`), region
   `westus2`, product "General Block Blob v2 Hierarchical Namespace",
   sku "Cool LRS", retrieved **2026-09-09**: Data Stored **0.01
   USD/GB-month**, Data Retrieval 0.01 USD/GB, Write Operations
   0.13 USD/10K, Read Operations 0.013 USD/10K, Early Delete
   0.01 USD/GB. The storage module tiers blobs to Cool after 14 days
   (`coolAfterDays=14`, `enableColdTier=false` in `infra/main.bicep`), so
   the steady-state corpus is priced entirely at Cool.
5. **Container Apps / Log Analytics prices**: as recorded in
   `config/lake/soak-aapl-spy.yaml`, same API, retrieved 2026-09-05 —
   vCPU 0.000034 USD/vCPU-s, memory 0.000004 USD/GiB-s, requests
   0.40 USD/1M, Log Analytics ingestion 2.30 USD/GB with the config's
   5 GB/month free allowance and its 0.25 GB per 1,000-request estimate.
6. **Environment fee excluded as a fixed cost**: a 0.10 USD/hour
   environment fee would accrue roughly 73 USD/month, yet measured
   month-to-date spend is 1.18 USD over 9 days — the dev environment is a
   consumption-only environment with no environment fee.
7. **Steady-state shape**: after backfill, each trading day adds one
   session per symbol per data type (21 sessions/symbol/data-type per
   month), written once as a blob, with inline ensure at the measured
   2.2403 s/session on 0.25 vCPU / 0.5 GiB. Stored data is retained
   indefinitely and priced at the Cool rate (no proration, no early
   deletion: objects stay at least 30 days).
8. **Egress delta: zero** — the API ingress is internal-only and storage
   is same-region; no public egress path is exercised by ingest or the
   soak posture.
9. **Retrieval contingency excluded from gate totals**: any research
   read-back of Cool bytes costs 0.01 USD/GB plus Cool read operations.
   The model exposes this as `monthly_retrieval_gb` (default 0). For
   scale: one full re-read of the watchlist quote corpus (~42 TB) would
   cost ~430 USD — a reason in itself to gate quote volume by liquidity.
10. **Log Analytics**: 30-day retention (`logRetentionDays = 30`);
    projected steady-state ingestion stays inside the 5 GB free allowance
    in every scenario, so the modeled LA line is 0.

Scenario meanings:

- `base` — current posture continuing: AAPL+SPY, bounded-depth ingest,
  6.0-year history. Steady state is negligible; the measured 3.94 USD/30d

  not the lake corpus.

  1,000-record ingest cap**: 11.8 GiB, 0.44 USD/month. It passes the gates
  but is explicitly **not full SIP depth**; it is listed to show the cap's
  effect, not as the rollout candidate.
- `watchlist` — the E6.5 broad backfill at full SIP depth (200 symbols,
  trade+quote, 2016-01-01 onward): 42,994 GiB, 430.26 USD/month. **Fails
  both gates.**
- `valve` — the recommended fallback: 200 symbols of trade history,
  quotes for the top-25 by liquidity, one-year history: 751 GiB,
  7.69 USD/month. **Passes both gates.**
- `scaled` — stress case (500 symbols, 3-year history, midpoint bytes):
  20,682 GiB, 208.20 USD/month. Fails; expansion beyond the valve needs a
  revised gate decision.

Reading: `decide()` on the broad-backfill projection fires
`QUOTE_HISTORY_VALVE` (both gate rows fail); `decide_with_spec()` solves
the largest liquidity-ranked valve that fits the 1 TiB ceiling at one-year
history (top-39 quotes). The conservative `valve` scenario (top-25) itself
evaluates to `APPROVE_BROAD_BACKFILL`, i.e. the valve-shaped rollout is
approvable as scoped. The one-time backfill window (bounded depth, one
replica, resumable across invocations) adds roughly 1.07M bounded ensure
requests of compute and blob writes — a one-time cost in the tens of
dollars spread over the backfill period, covered by the budget guardrails
during execution.

## What T051 Receives (handoff)

1. Universe: 200 symbols (documented assumption standing in for the
   "200-plus" universe; replace with the concrete ranked list when
   defined).
2. History policy: trades for all 200, all available sessions; quotes for
   the top-N by liquidity (recommended initial N=25, computed maximum
   N=39) with one-year history.
3. Ranking criterion: liquidity rank ascending — most liquid first
   (e.g., SPY, QQQ, AAPL head the ranked list); T051 owns producing the
   ranked list.
4. Guards: every configured budget alert and the 1 TiB capacity pause
   stay active; re-run this model with `--decisions` before widening N.
5. Price refresh: re-verify Cool tier and Container Apps prices via the
   Retail Prices API before execution; update this document and the model
   constants together.
